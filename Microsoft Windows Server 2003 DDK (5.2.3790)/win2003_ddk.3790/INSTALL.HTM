Getting Started

The Microsoft® Windows® Server 2003 Driver Development Kit (DDK) provides a development environment for the creation of drivers for Windows Server 2003, Windows XP, and Windows 2000. The DDK provides additional driver-specific headers, libraries, sources, tools, and documentation that are used to develop drivers for Windows Server 2003.

This document presents an overview of the Microsoft® Windows® Driver Development Kit (DDK) for Windows Server 2003 and provides essential installation information for this driver development kit. Before installing the DDK, read through this document to determine whether or not to install optional DDK components and how to set up your systems for a trouble-free installation. Installing the DDK

To install the Microsoft® Windows® Driver Development Kit for Windows Server 2003, you must be able to access a CD-ROM drive from Windows, either locally or through a network.

A development machine running Windows Windows NT® 4.0, Windows 95, Windows 98, or Windows Me is not supported when developing drivers for Windows 2000, Windows XP, or Windows Server 2003.

Developing 16-bit drivers (for example, VxD and WinMe) is not supported on a Windows 64-bit platform.

System Requirements

The system requirements for using this DDK on a driver-development machine are:

  • Microsoft® Windows® Server 2003, Windows XP, Windows XP Service Pack 1, or Windows 2000.
  • CD-ROM drive or Internet access.
  • At least 128MB RAM. 256MB of RAM or more is recommended.
  • At least 574MB hard-disk space for a full installation. Significantly more space may be required to compile all samples; up to 900MB may be required.

The system requirements for using this DDK on a driver-testing machine are:

  • Microsoft Windows Server 2003 for Windows Server 2003 driver development.
  • At least 128MB RAM if you are running a free or retail build of Windows Server 2003, or 256MB RAM if you are running a checked build. In some cases, checked builds may require only 128MB of RAM, depending on the particular drivers loaded on the machine.
  • A second machine that is capable of running Windows 2000, Windows XP, or Windows Server 2003 for kernel debugging of your under-development drivers. This machine can be your driver-development system if desired.

DDK Installation

Note:    You must have Administrator privileges to correctly install the DDK.

Note:    Do not install this DDK over previous versions of this or any other DDK. Improper installation of the DDK can cause the use of old and incorrect files, which will lead to unreliable results in any drivers you develop.

Note:  The installation path and icon placement have been changed. The default installation path is now x:\WinDDK\Kit <BldNum>. The icons can be found at Programs\Development Kits\DDK Kit <BldNum>.

To install the DDK, perform the following steps:

  1. Execute the setup.exe file from the CD-ROM.
  2. If installing on a Windows 2000 computer, answer 'Run the program from it's current location' to the question,which asks "What would you like to do with this file?" OR If installing on a Windows Server 2003 or Windows XP computer, answer 'Open' to the question, which asks "Would you like to open the file or save it to your computer?"
  3. Click the Next button to install the Windows DDK.
  4. Read and accept the Software License Agreement.
  5. Click the Next button to proceed.
  6. Select the installation path (it is suggested to use the path that is displayed).
  7. Click the Next button to proceed.
  8. Choose the components that you would like to install.
  9. Click the Next button to proceed.
  10. Confirm that you want to install the DDK by verifying that the installation path is correct.
  11. Click the Next button to install the kit.

Note:    On machines with large hard disk sectors such as "FAT 16" file systems, the setup program may miscalculate the amount of space needed to attempt an installation even though the space is not available.

Installing the Debuggers

The Debugging Tools for Windows package features WinDbg, a powerful debugger with a graphical interface that can debug both user-mode and kernel-mode code. This package also includes the debuggers KD, NTSD, and CDB, and many additional tools. The documentation in this package describes the use of these debuggers and includes tips for user-mode and kernel-mode debugging.

Debugging Tools for Windows is available in 32-bit and 64-bit versions. The 32-bit version is appropriate for most users. However, if you are planning on debugging an application on an IA-64 based processor, you should select the 64-bit version. The 64-bit version can be installed only on 64-bit versions of Windows.

These debugging tools require approximately 21 MB of hard disk space.

To obtain the most current version of Debugging Tools for Windows, see  Microsoft Debugging Tools.

If you cannot install Debugging Tools for Windows from this internet site, then use one of the following links:

  1. Install 32-bit Debugging Tools for Windows (Required for most customers)
  2. Install 64-bit Debugging Tools for Windows

Symbols

The new linker strips all debug information from the SYS file and moves the data into a PDB file. The PDB file should be copied to the symbols directory for debugging. Copying the SYS file will not provide debugging information.


Verifying Driver Development Kit Installation

To verify that you have properly installed the Windows Server 2003 DDK, perform the following steps:

  1. Start a command window with environment variables set for a Windows Server 2003 checked build environment, using the Programs/Development Kits/Windows DDK <BldNum>/Build Environments/Windows Server 2003/Windows Server 2003 Checked Build Environment menu item.
  2. In the command window, type the command build –cZ. This command compiles and links the complete set of installed sources. This can take more than 30 minutes to complete, depending on which DDK components are installed and the system on which the build is being performed.
  3. The build command should complete with no errors and no warnings displayed.
