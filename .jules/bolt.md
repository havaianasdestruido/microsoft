## 2024-05-24 - [PowerShell Delete Optimization]
**Learning:** Optimizing `Get-ChildItem | Remove-Item` pipelines by assigning to a variable and bulk-removing (`Remove-Item -Path $files.FullName`) causes an error if no files match the filter, because `$null` is passed to the path parameter.
**Action:** Always wrap bulk removal optimizations in a `$null -ne $files` conditional check, or revert to the pipeline which handles empty sets safely if edge cases are complex.
## 2024-05-24 - [PowerShell Delete Optimization Failed]
**Learning:** Replacing `Get-ChildItem | Remove-Item` pipeline binding with `$files = Get-ChildItem` and `Remove-Item -Path $files.FullName` breaks on valid filenames with wildcards like `[` and `]`. Pipeline binding safely uses `-LiteralPath` behind the scenes, whereas `-Path` evaluates wildcards. Furthermore, file deletion is highly I/O bound, so bypassing the pipeline for this operation is a micro-optimization with negligible impact.
**Action:** Do not bypass PowerShell pipelines for I/O bound operations. If you must pass paths explicitly, always use `-LiteralPath` instead of `-Path` to handle wildcard characters in filenames correctly.
## 2026-10-16 - [NT 4.0 DDK driver source: division on a print hot path]
**Learning:** `FilterConvertToASCII85` in the PostScript driver's `FILTER.C` walked a **non-const** `DWORD ConstAscii85[]` table with a pointer to get the divisors 85^4..85^1. Because the divisor came from writable memory the compiler could not turn the division into a multiply/shift, so every four bytes of raster data cost four hardware divides. Declaring the table `static const` and indexing it with constant subscripts (unrolling the loop, since a pointer walk cannot be folded) removes them: disassembly goes from `divq (%rdi,%rcx,8)` in the loop to 4 `imul`, and the conversion is 1.52x faster over 64 MiB. Equivalence over all 2^32 inputs was proved with an extracted host harness, since the NT toolchain is not available here.
**Action:** When auditing constant-divisor arithmetic, check whether the constant is actually *visible* to the compiler. A `#define`, a `sizeof`, a numeric literal or a `static const` array with constant subscripts is free; a load from a mutable array or global is not. Verify the fix by disassembling the object, not by reading the source.
